## نبذة عن المشروع

**NCA Parking** هو تطبيق ويب مخصص لتنظيم بيانات المركبات المسجلة في بيئة الأكاديمية الوطنية للبناء، بهدف تسهيل الوصول إلى صاحب المركبة عند الحاجة، مثل حالات الوقوف الخاطئ أو إعاقة مركبة أخرى.

المشروع مبني كتطبيق ويب ثابت من جهة الواجهة، ويستخدم **Supabase** لخدمات قاعدة البيانات والمصادقة والتخزين.

> هذا المستودع يمثل الشفرة البرمجية للمشروع. أي شعارات أو علامات تجارية تخص الأكاديمية الوطنية للبناء أو أطرافًا أخرى تبقى حقوقها لأصحابها، ولا يعني ظهورها في المشروع انتقال ملكيتها أو منح ترخيص مستقل باستخدامها.

## الوظائف الرئيسية

### تسجيل المركبات

يمكن للمستخدم تسجيل مركبته وإدخال البيانات الأساسية، ومنها:

- اسم صاحب المركبة.
- نوع / موديل المركبة.
- رقم اللوحة.
- اللون.
- رقم الهاتف.
- مجال التدريب.
- صورة اختيارية للمركبة.

يتم ربط التسجيل بمعرف محلي للجهاز لتمكين المستخدم من الوصول إلى مركباته المسجلة من المتصفح نفسه.

### منع التسجيل المكرر

قبل إنشاء سجل جديد، يتحقق النظام من وجود تسجيل نشط مطابق للبيانات الأساسية.

كما تعتمد قاعدة البيانات على فهرس فريد للسجلات النشطة لمنع إنشاء نسخ متطابقة عن طريق الطلبات المباشرة.

السجل الذي تم تعطيله (`inactive`) لا يمنع إعادة تسجيل المركبة نفسها مستقبلًا.

### صفحة «سياراتي المسجلة»

يوفر النظام صفحة مستقلة تعرض المركبات النشطة المرتبطة بمعرف الجهاز الحالي فقط، بدل عرض جميع مركبات النظام.

من خلالها يستطيع صاحب المركبة الوصول إلى خيارات الإدارة المسموح بها لمركباته.

### تعديل بيانات المركبة

يمكن لصاحب المركبة تعديل بيانات مركبته من الجهاز المرتبط بالتسجيل.

يتم التحقق من الملكية في الواجهة، كما يتم إرسال معرف الجهاز مع طلبات Supabase حتى تستطيع سياسات **Row Level Security (RLS)** التحقق من صلاحية العملية.

### الحذف الآمن

زر الحذف لا يمسح سجل المركبة نهائيًا من قاعدة البيانات.

بدلًا من ذلك، يتم تغيير حالة المركبة من:

```text
active
```

إلى:

```text
inactive
```

ويتم تنفيذ ذلك عبر دالة قاعدة بيانات مخصصة:

```text
deactivate_my_car
```

وبذلك تختفي المركبة من القوائم النشطة مع بقاء السجل محفوظًا في قاعدة البيانات.

### البحث

يدعم النظام البحث بين المركبات النشطة بواسطة:

- رقم اللوحة.
- اسم صاحب المركبة.
- موديل المركبة.

### التواصل مع صاحب المركبة

تحتوي بطاقات المركبات على وسائل تواصل مباشرة:

- **اتصال هاتفي**.
- **واتساب**.

يقوم النظام بتهيئة أرقام الهواتف السعودية قبل الاتصال أو فتح واتساب، كما ينشئ رسالة واتساب جاهزة تتضمن اسم صاحب المركبة ورقم اللوحة عند توفره.

### رفع صور المركبات

يدعم النظام:

- اختيار الصور من الجهاز.
- السحب والإفلات.
- معاينة الصورة قبل الحفظ.
- ضغط الصور الكبيرة تلقائيًا عند الحاجة.
- رفع الصور إلى **Supabase Storage** داخل bucket باسم:

```text
car-images
```

### عداد المركبات

يظهر في أعلى الموقع عداد للمركبات النشطة المسجلة، ويتم تحديثه من قاعدة البيانات.

### الوضع الليلي

يدعم الموقع الوضعين:

- الوضع الفاتح.
- الوضع الليلي.

ويتم حفظ تفضيل المستخدم محليًا في المتصفح.

### إدارة النظام

توجد وظائف إدارية تعتمد على **Supabase Auth**، وتشمل تسجيل دخول المدير وأدوات إدارة مخصصة تظهر بعد نجاح المصادقة.

## قاعدة البيانات

يعتمد التطبيق على جدول رئيسي للمركبات باسم:

```text
cars
```

ومن الحقول المستخدمة في النظام:

```text
id
owner_name
car_model
plate_number
car_color
phone_number
training_field
device_id
car_image
status
created_at
updated_at
```

حالة المركبة تعتمد على قيمة `status`، وتظهر في الموقع المركبات التي تكون حالتها:

```text
active
```

بينما المركبات التي تم حذفها حذفًا آمنًا تصبح:

```text
inactive
```

## حماية التكرار

يتم منع السجلات المتطابقة بين المركبات النشطة باستخدام منطق تحقق في الواجهة وقيد فريد في PostgreSQL.

المبدأ الحالي هو:

```text
نفس بيانات المركبة + status = active
→ يمنع إنشاء نسخة جديدة
```

أما إذا كانت النسخة السابقة:

```text
status = inactive
```

فيمكن إعادة تسجيل المركبة مرة أخرى.

## الأمان والصلاحيات

يستخدم المشروع **Supabase Row Level Security** للتحكم في الوصول إلى البيانات.

من عناصر التصميم الأمني الحالي:

- السماح بعرض المركبات النشطة وفق السياسات المحددة.
- التحكم في عمليات الإضافة.
- التحقق من ملكية المركبة قبل تعديلها.
- إرسال معرف الجهاز في الهيدر `x-device-id` مع طلبات Supabase.
- تنفيذ الحذف الآمن من خلال دالة قاعدة بيانات مخصصة.
- استخدام Supabase Auth لعمليات المدير.

### ملاحظة مهمة حول معرف الجهاز

يتم إنشاء معرف محلي وتخزينه في:

```text
localStorage
```

تحت المفتاح:

```text
parking_device_id
```

هذا المعرف مخصص لربط المركبات بالمتصفح المستخدم، وليس بديلًا كاملًا عن حساب مستخدم موثق.

حذف بيانات المتصفح أو استخدام جهاز / متصفح مختلف قد يؤدي إلى إنشاء معرف جهاز جديد، وبالتالي لن يتعرف الموقع تلقائيًا على التسجيلات السابقة باعتبارها «سياراتي».

## متطلبات التشغيل

لتشغيل المشروع كاملًا تحتاج إلى:

1. استضافة ملفات الواجهة.
2. مشروع Supabase.
3. جدول `cars` بالحقول والسياسات المطلوبة.
4. تفعيل RLS.
5. إعداد دوال قاعدة البيانات المطلوبة، ومنها دالة الحذف الآمن.
6. إعداد Supabase Storage bucket باسم `car-images`.
7. إعداد حساب إداري في Supabase Auth عند استخدام أدوات المدير.
8. ضبط النطاق المخصص إذا رغبت في استخدام دومين مستقل.

## إعدادات Supabase

يحتوي `app.js` على إعدادات الاتصال الخاصة بعميل Supabase المستخدم في المتصفح.

**لا تضع أبدًا** في ملفات الواجهة أو GitHub العام:

- `service_role` key.
- كلمات مرور المدير.
- كلمات مرور قاعدة البيانات.
- أي مفتاح إداري أو سر خاص بالخادم.

يجب أن تظل الأسرار الإدارية خارج الشفرة العامة.

## ملاحظات للمطور

عند تحديث ملفات JavaScript أو CSS، يستخدم المشروع query version في `index.html` لتقليل مشاكل الكاش، مثل:

```html
<link rel="stylesheet" href="styles.css?v=VERSION" />
<script src="app.js?v=VERSION"></script>
```

عند نشر نسخة جديدة يمكن تغيير قيمة `VERSION` حتى تحصل الأجهزة على الملف المحدث بدل نسخة محفوظة في الكاش.
